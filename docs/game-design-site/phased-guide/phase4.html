Phase 4: データファイルの作成

📦 Phase 4: データファイルの作成

ゲームコンテンツの追加 - 魚種、装備、装飾のデータ

🎯 何を作るか（What to Build）

Phase 4では、ゲームのコンテンツデータを外部ファイルとして管理します。これまではコード内にハードコードしていたデータを、編集しやすいJSON形式で管理できるようにします。

💡 データ駆動設計とは？
ゲームのコンテンツ（魚の種類、装備など）をコードから分離し、データファイルで管理する設計手法です。プログラマーでなくても、データを編集してゲームを拡張できます。

作成するファイル：

  • ✅ fish_species.json: 15種類以上の魚のデータ（名前、適温、価格など）
  • ✅ equipment.json: 10種類以上の装備データ（フィルター、ヒーターなど）
  • ✅ decorations.json: 15種類以上の装飾データ（岩、水草など）
  • ✅ DataLoaderクラス: これらのJSONファイルを読み込むシステム
  • ✅ バランス調整ガイド: ゲームバランスの調整方法のドキュメント
✨ 完成イメージ
JSONファイルを編集するだけで、新しい魚や装備を追加したり、価格やパラメータを調整できるようになります。

🤔 なぜこう作るか（Why Build This）

1. なぜデータをコードから分離するのか？

データ分離の利点：

  • メンテナンス性: データの修正にコードの再コンパイル・再起動が不要
  • 拡張性: 新しいコンテンツを簡単に追加できる
  • バランス調整: ゲームバランスを調整しやすい（テストプレイ後の微調整が楽）
  • チーム作業: プログラマー以外（企画者など）もデータ作成に参加できる
  • 国際化: 言語別のデータファイルを作成しやすい

2. なぜJSON形式を使うのか？

JSON（JavaScript Object Notation）を選ぶ理由：

  • 可読性: 人間が読み書きしやすい形式
  • 標準ライブラリ: Pythonの標準jsonモジュールで簡単に扱える
  • 構造化: ネストしたデータ構造を表現できる
  • 広く使用: 多くのツールやエディタがサポート
  • 軽量: XMLより簡潔で、ファイルサイズが小さい

3. なぜDataLoaderクラスが必要なのか？

専用のローダークラスを作る理由：

  • 一元管理: データ読み込みのロジックを1か所に集約
  • エラーハンドリング: ファイル読み込みエラーを適切に処理
  • キャッシング: 一度読み込んだデータを再利用して高速化
  • バリデーション: データの整合性をチェック
  • 拡張性: 将来的に他のデータソース（DB等）にも対応可能

✍️ どう書くか（Coding Style & Best Practices）

1. JSONファイルの書き方

JSONは可読性が重要です：

{
  "fish_species": [
    {
      "id": "goldfish",              // ← IDは英語で（プログラムで使用）
      "name": "金魚",                 // ← 表示名は日本語OK
      "min_temperature": 18.0,       // ← 小数点を明示
      "max_temperature": 26.0,
      "preferred_ph": 7.0,
      "ph_tolerance": 1.0,
      "base_price": 500,             // ← 整数は小数点なし
      "description": "初心者向けの丈夫な魚"  // ← 説明は詳しく
    }
  ]
}

ポイント:

  • インデントは2スペースまたは4スペース（統一する）
  • フィールド名はスネークケース（lower_case）
  • 数値型と文字列型を正しく使い分ける

2. DataLoaderクラスの設計パターン

シングルトンパターンを使用する理由：

class DataLoader:
    _instance = None
    _cache = {}
    
    def __new__(cls):
        """シングルトンパターン: インスタンスを1つだけ作成"""
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

このパターンにより、データを1回だけ読み込んで再利用できます。

3. エラーハンドリングの書き方

データ読み込みでは、明確なエラーメッセージが重要です：

try:
    with open(file_path, 'r', encoding='utf-8') as f:
        data = json.load(f)
except FileNotFoundError:
    raise FileNotFoundError(
        f"データファイルが見つかりません: {file_path}\n"
        f"ファイルが存在するか確認してください。"
    )
except json.JSONDecodeError as e:
    raise ValueError(
        f"JSONの形式が不正です: {file_path}\n"
        f"エラー箇所: 行{e.lineno}, 列{e.colno}\n"
        f"メッセージ: {e.msg}"
    )

4. データバリデーションの書き方

データの整合性をチェックする関数を作ります：

def validate_fish_data(self, fish_data: dict) -> bool:
    """魚データのバリデーション"""
    required_fields = [
        'id', 'name', 'min_temperature', 'max_temperature',
        'preferred_ph', 'ph_tolerance', 'base_price'
    ]
    
    # 必須フィールドのチェック
    for field in required_fields:
        if field not in fish_data:
            raise ValueError(f"必須フィールド '{field}' がありません")
    
    # 温度範囲のチェック
    if fish_data['min_temperature'] >= fish_data['max_temperature']:
        raise ValueError("min_temperature は max_temperature より小さい必要があります")
    
    # 価格のチェック
    if fish_data['base_price'] <= 0:
        raise ValueError("base_price は正の数である必要があります")
    
    return True

🐠 fish_species.json の完全実装

データ構造の設計思想

fish_species.jsonは、ゲーム内の全魚種のマスターデータです。各魚には以下の情報を含めます：

  • 基本情報: ID、名前、説明、カテゴリ、レアリティ
  • 経済情報: 購入価格、売却価格
  • 成長情報: 初期サイズ、最大サイズ、成長率、寿命
  • 飼育条件: 温度、pH、水槽サイズ、相性
  • ステータス: 体力、空腹率、ストレス感受性、病気耐性
  • 魅力度: 美しさ、レアリティボーナス、来客への魅力
